# Деплой

Всё, что нужно сделать человеку — добавить два секрета в GitHub. Установку
Node, pm2, nginx, выпуск HTTPS-сертификата, раскладку файлов, перезапуск и
настройку кнопки бота деплой делает сам.

## 1. Секреты в GitHub

Вся конфигурация деплоя живёт **только** в секретах Actions. В репозитории
никаких значений нет и быть не должно: `.env` для сервера собирается на
раннере из этих секретов при каждом деплое. Файл `server/.env.example`
нужен исключительно для локальной разработки и на сервер не попадает.

`Settings → Secrets and variables → Actions → New repository secret`

### Обязательные

| Имя | Что это |
|---|---|
| `SSH_HOST` | IP сервера (или домен, если есть) |
| `SSH_PASSWORD` | пароль от SSH — **либо** вместо него `SSH_PRIVATE_KEY` (приватный ключ целиком, вместе со строками `-----BEGIN...`/`-----END...`) |

Пароль и ключ взаимозаменяемы: задан пароль — деплой заходит по паролю
(через `sshpass`, пароль передаётся переменной окружения, а не аргументом
командной строки, чтобы не светиться в списке процессов); задан ключ —
по ключу. Если заданы оба, используется пароль.

### Остальные

| Имя | По умолчанию | Когда задавать |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота от @BotFather (см. ниже) |
| `SSH_USER` | `root` | если заходите под другим пользователем (нужен passwordless sudo) |
| `SSH_PORT` | `22` | если SSH на другом порту |
| `DEPLOY_PATH` | `/opt/system-dynamics-ui` | если нужен другой каталог |
| `APP_DOMAIN` | `<ip>.sslip.io` | если есть свой домен, направленный на этот сервер |

### Что даёт `TELEGRAM_BOT_TOKEN`

Токен нужен серверу, чтобы проверять подпись `Telegram.WebApp.initData`:
без этой проверки нельзя открывать API записи на диск — писать в него смог
бы любой желающий. Поэтому поведение зависит от того, задан ли он:

- **задан** → сценарии сохраняются файлами на диске сервера
  (`${DEPLOY_PATH}/data/scenarios/<id пользователя>/`), и деплой сам
  привязывает WebApp к кнопке бота через `setChatMenuButton`;
- **не задан** → `/api/health` отдаёт `scenarios: false`, фронтенд это
  видит и сохраняет сценарии в облако Telegram (CloudStorage — привязано к
  аккаунту, доступно со всех устройств). Приложение полностью рабочее,
  но кнопку бота придётся назначить руками в @BotFather.

Деплой из-за отсутствия токена не падает — это осознанный выбор, чтобы
приложение можно было поднять и проверить до того, как заведён бот.

## 2. Запуск

После добавления секретов: **Actions → CI/CD → Run workflow → ветка `main`**.
Пустой коммит не нужен. Дальше деплой идёт сам на каждый push в `main`.

## 3. Что именно делает деплой

1. **Тесты и сборка** — vitest для `web/` и `server/`, репетиция скриптов
   деплоя в песочнице, `vite build`.
2. **Подготовка сервера** (`deploy/bootstrap.sh`, идемпотентно):
   ставит `rsync`, `curl`, `nginx`, `certbot`, Node.js 20 и `pm2` — если
   чего-то нет; создаёт каталоги; настраивает nginx-прокси на порт 3000;
   выпускает сертификат Let's Encrypt; включает автозапуск после
   перезагрузки сервера. Скрипт уходит на сервер по stdin, поэтому на нём
   заранее не нужно вообще ничего.
3. **Раскладка** — `rsync --delete` в `${DEPLOY_PATH}/app`. Каталог с
   данными лежит рядом (`${DEPLOY_PATH}/data`), поэтому сохранённые
   сценарии переживают любой деплой.
4. **Запуск** (`deploy/release.sh`) — `npm ci --omit=dev`,
   `pm2 startOrReload`, затем health-check: если приложение не ответило за
   30 секунд, деплой падает и печатает последние 50 строк логов pm2.
5. **Проверка снаружи** — `https://<домен>/api/health`.
6. **Кнопка бота** — если задан `TELEGRAM_BOT_TOKEN`, вызывается
   `setChatMenuButton`, и WebApp появляется у бота рядом с полем ввода.

Итоговый адрес приложения пишется в summary прогона.

## 4. HTTPS без своего домена

Telegram требует HTTPS с доверенным сертификатом. Домен покупать не нужно:
используется [sslip.io](https://sslip.io) — публичный DNS, где имя вида
`203-0-113-42.sslip.io` резолвится в IP `203.0.113.42`. Имя реально
резолвится, поэтому Let's Encrypt спокойно выдаёт на него сертификат.
Домен вычисляется из `SSH_HOST` автоматически.

Если появится свой домен — направьте его на сервер и задайте секрет
`APP_DOMAIN`; код менять не нужно.

## 5. Если что-то пошло не так

Ошибки сформулированы человеческим языком прямо в логе прогона:

| Сообщение | Что делать |
|---|---|
| `Permission denied (publickey,password)` | неверный `SSH_PASSWORD`/`SSH_PRIVATE_KEY` или `SSH_USER` |
| `нужен root или passwordless sudo` | задать `SSH_USER=root` или разрешить пользователю sudo без пароля |
| `не удалось выпустить сертификат` | открыть порт 80 в firewall хостера (Let's Encrypt проверяет домен по нему) |
| `HTTPS снаружи не отвечает` | открыть порт 443 в firewall хостера |
| `/api/health не ответил за 30 секунд` | ниже в логе — 50 строк логов pm2 с причиной падения |

## 6. Локальная разработка

```bash
npm run install:all
npm run dev:server    # backend на :3000
npm run dev:web        # frontend на :5173, /api проксируется на :3000
```

Вне Telegram приложение работает как обычная страница: `Telegram.WebApp`
отсутствует, сценарии сохраняются в localStorage браузера.

## 7. Где лежат сценарии

```
${DEPLOY_PATH}/data/scenarios/<telegram_user_id>/manifest.json   — список сценариев
${DEPLOY_PATH}/data/scenarios/<telegram_user_id>/<uuid>.json     — сами сценарии
```

Имена файлов — сгенерированные сервером UUID, поэтому произвольный ввод в
URL не даёт доступа за пределы каталога пользователя.
