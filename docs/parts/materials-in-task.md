# Часть «Материалы в задаче и на проверке»

Заготовки для `docs/CHANGELOG.md` и `docs/ARCHITECTURE.md` — вливаются в общие файлы при слиянии частей.

## Для CHANGELOG.md

## 2026-09-12 — Материалы на входе задачи и материалы сдачи на «Проверке»

- **Для чего:** владелец: «исполнитель на вкладке «Задача» и на форме задачи должен видеть единицы ресурсов, которые потребляет ответственная функция, и иметь возможность их скачать»; «в вкладке «Проверка» должна быть возможность увидеть все материалы, которые являются единицами потреблённого и выданного ресурса, и скачать их».
- **Почему:** единицы входа показывались только в момент сдачи — кнопками «взял» — а работать с заявкой нужно до того, как работа сделана, и скачать её было неоткуда. Проверяющий видел числа «взято: заявки 1 · выдано: договоры 1» и ссылки только у старых сдач с общим полем `files`; вещи новых сдач (`units`, коды с подтверждением) и то, из чего они сделаны (`took`), на «Проверке» не читались вовсе.
- **Почему мы решили именно так:** один список единиц (`unitsOf`) и одно правило ссылки на всё приложение: `textHref` переехал из «Отчётов» в `storage.js` рядом с `reportSrc`, строка единицы — в `UnitLinks.jsx`, и та же строка стоит в форме задачи и на «Проверке» — одна вещь зовётся и скачивается одинаково везде. На входе показываются только неизрасходованные (`spentIds`): израсходованной больше нет ни у кого. Непринятые не прячутся — так же, как при выборе «взял». На карточке доски — только число: карточка узкая, ссылки — в открытой задаче. Взятое, если исполнитель не назвал номера, не достраивается по количествам — сказано словами «какие именно — не названо», с количеством по ресурсу. Выданное берётся строками `unitsOf` последней сдачи: у прежних сдач с общим `files` строка одна на ресурс, и она читается и скачивается как раньше. У кода в списке сам код и ссылка «скачать подтверждение» (`sb.proof`).
- **Кому/для чего это подойдёт:** исполнителю, который открыл задачу и берёт материалы в работу; проверяющему, который принимает работу по тому, что вышло, а не по числу «1».
- **Меняет ли другой функционал:** нет. Модель и сдачи не менялись — читаются те же поля (`units`, `took`, `takes`, `proof`, старое `files`). `ReviewBoard` получил проп `materials` (без него единицы, положенные руками, на «Проверке» не находились бы по `took`). «Отчёты» используют тот же `textHref`, только из `storage.js`.
- **Метрики и когда оценивать результат:** сразу — исчезли ли вопросы «где скачать заявку, по которой делать задачу»; к первым приёмам — открывает ли проверяющий вещи из карточки «Проверки», а не через «Отчёты».

## Для ARCHITECTURE.md — строки таблицы понятий

| Понятие | Где в коде | Как устроено |
|---|---|---|
| Материалы задачи | `lib/taskUnits.js` (`inputUnits`, `inputCount`, `tookUnits`, `givenUnits`), строка единицы `components/UnitLinks.jsx` (`UnitList`, `unitDownload`), блок «материалы на входе» в `TaskView` и число на карточке доски (`TasksBoard.jsx`), блок «материалы» в `Card` (`ReviewBoard.jsx`) | Что лежит на входе функции и что вышло из сдачи — вещами, а не числом. Вход: по каждому `takes` единицы этого ресурса из `unitsOf` минус `spentIds`; непринятые показаны с пометкой. Сдача на «Проверке»: «взято» — единицы по `sb.took` (не названы → слова «какие именно — не названо» с количеством из `takes`), «выдано» — строки `unitsOf` этой (последней) сдачи, у кода — сам код и ссылка на `sb.proof`. Ссылка одна на всё приложение: файл → `reportSrc`, текст/код → `textHref` (`storage.js`), имя файла как в «Отчётах». `ReviewBoard` получает `materials`, иначе единицы, положенные руками, не находятся по номерам. |

Пункт инварианта (раздел 5): у единицы ресурса одна ссылка на скачивание на всё приложение — `reportSrc` для файла, `textHref` для текста и кода; новое место, где единицу дают скачать, использует `UnitLinks.jsx`, а не свою ссылку.
