# Схема жизнеспособности — Telegram Mini App

**Развёрнуто:** https://144-124-240-20.sslip.io — открывается кнопкой у бота
в Telegram. Обновляется автоматически при push в `main`.

Модель бизнес-системы, упакованная как Telegram Mini App с сохранением
сценариев на диск сервера.

Модель — это набор **активов**. Актив состоит из трёх вещей: **воркеров**
(исполнители и проверяющие), **функций**, которые они выполняют, и
**ресурсов**, которые функции потребляют и передают. Функция может только
взять и дать: взять несколько ресурсов и выдать несколько других, а выданное
— передать в другой актив. Сколько берётся и выдаётся — диапазон: сначала он
закладывается как гипотеза, потом уточняется реальными выполнениями. У
функции есть время одного выполнения, и из него выходит, сколько раз она
срабатывает за месяц.

Отсюда весь расчёт (`web/src/lib/plan.js`): прогноз — лента между нижней и
верхней границей, а поверх неё ложится линия факта по принятым выполнениям.
Задача в приложении и есть одно выполнение функции.

И обратный вопрос, который нужнее прямого: **поставил цель на ресурсе —
приложение говорит, что для неё надо сделать**: сколько выполнений какой
функции, сколько это работы и сколько времени займёт по самой длинной
цепочке. Подробности и инварианты — в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), разбор каждого изменения — в
[`docs/CHANGELOG.md`](docs/CHANGELOG.md).

## Структура репозитория

```
web/                    React + Vite фронтенд (сама модель + Telegram-обвязка)
  index.html             Модель: главное мини-приложение
  call.html              Звонок: ОТДЕЛЬНОЕ мини-приложение (/call), свой бандл
  src/components/SystemModel.jsx  Модель: схема, карточка актива, прогноз
  src/components/AssetPanel.jsx   Актив: воркеры, функции, ресурсы
  src/components/TasksBoard.jsx   Задачи: выполнения функций и канбан
  src/components/CallApp.jsx      Окно звонка: ни вкладок, ни модели
  src/lib/funcs.js       Запись активов и функций, проверки строения
  src/lib/plan.js        Расчёт по функциям: лента прогноза, факт, передачи
  src/lib/history.js     История правок модели: отмена и возврат
  src/lib/draft.js       Черновик: страховка от закрытия вкладки
  src/storage.js         Хранилище сценариев: сервер → облако Telegram → браузер
server/                 Express-бэкенд: отдаёт фронтенд + API /api/scenarios
codes/                  Сервис кодов и биллинг: ключи, токены, планы, подписки, оплата, админ-бот (docs/DEPLOYMENT.md 6.8)
locales/          — словари интерфейса и бота: en.json, zh.json (ключ — русская строка); scripts/i18n-extract.mjs собирает ключи
  public/admin.html      Панель подписок (мини-приложение админ-бота)
  src/lib/links.js       Ссылка-приглашение на звонок (только отдельное приложение)
deploy/
  bootstrap.sh           Приводит чистый VPS в рабочее состояние (идемпотентно)
  release.sh             Установка зависимостей, перезапуск, health-check
  rehearse.sh            Репетиция bootstrap.sh в песочнице (гоняется в CI)
docs/
  ARCHITECTURE.md        Карта «парадигма → код», инварианты
  ROADMAP.md              Куда двигаемся дальше
  CHANGELOG.md            Шаблон описания изменений + журнал
  DEPLOYMENT.md            Секреты и как всё разворачивается
.github/workflows/ci-cd.yml   Тесты на каждый push, деплой на push в main
```

## Где сохраняются сценарии

Слой `web/src/storage.js` выбирает хранилище сам:

1. **диск сервера** — если развёрнут `server/` и задан токен бота;
2. **облако Telegram** (CloudStorage) — если сервера нет или токен не задан;
3. **localStorage** — если приложение открыли вне Telegram.

Вызывающий код одинаковый во всех трёх случаях, в интерфейсе подписано,
куда именно идёт сохранение.

## Быстрый старт (локально)

```bash
npm run install:all
npm run dev:server    # http://localhost:3000
npm run dev:web        # http://localhost:5173 (проксирует /api на :3000)
```

Открыть `http://localhost:5173` в браузере — вне Telegram приложение
работает как обычная веб-страница (Telegram SDK просто не активируется).

## Тесты и сборка

```bash
npm test               # web (vitest + RTL) и server (vitest + supertest)
npm run build           # production-сборка фронтенда → web/dist
```

## Деплой на прод

От человека нужны **два секрета** в GitHub: `SSH_HOST` и `SSH_PASSWORD`
(либо `SSH_PRIVATE_KEY`, если вход по ключу).
Всё остальное деплой делает сам — ставит Node/pm2/nginx, выпускает
HTTPS-сертификат (домен не нужен, используется `sslip.io`), раскладывает
файлы, перезапускает и проверяет, что приложение отвечает.

Подробности — в [`docs/DEPLOYMENT.md`](./docs/DEPLOYMENT.md).
